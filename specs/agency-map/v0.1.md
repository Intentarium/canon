# Agency Map v0.1

An Agency Map makes the operating logic of a system explicit before tools or automation accelerate it.

## The eight elements

1. **Intent** — the outcome, success signals, and deliberate non-goals.
2. **Actors** — people, teams, services, agents, and external parties that participate.
3. **Authority** — which actor may decide, approve, execute, override, or stop; within what scope and under which conditions.
4. **Boundaries** — what must not happen and how the boundary is enforced.
5. **Trust signals** — current evidence that permits an actor to proceed.
6. **Evidence** — durable proof of what happened, why, and under whose authority.
7. **Escalation** — the route taken when authority, confidence, or conditions are insufficient.
8. **Feedback** — the signals, ownership, and cadence through which the system learns.

## Method

Start with the outcome rather than the current workflow. Name actors by role, not individual, unless identity is itself a control. Describe authority as explicit actions over a bounded scope. Separate trust signals used before execution from evidence produced by execution. Make every escalation trigger observable and every feedback loop owned.

An Agency Map is incomplete when accountability exists without matching authority, a boundary lacks enforcement, a trust signal has no freshness expectation, or feedback has no owner and response.

## Use

The method is intentionally domain-independent. It can describe a deployment pipeline, an organizational decision, an AI-assisted workflow, a live-production process, or a personal operating system without pretending those systems share the same implementation.

The normative machine contract is [`schemas/agency-map.schema.json`](../../schemas/agency-map.schema.json). Version `0.1.0` is experimental and may change incompatibly before `1.0.0`.
